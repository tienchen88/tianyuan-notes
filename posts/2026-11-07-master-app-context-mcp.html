Cole Medin 這支很短：agent 看得懂程式碼，卻看不到 app 實際在跑的樣子

晚上照例看一下有沒有新片，Cole Medin 上了 Your Coding Agent Knows Your Code, But Not Your Actual App (Here's the Fix)。

先講清楚，這支很短，字幕加起來大概一分半，而且整支就是跟 OutSystems 合作的業配，他最後也有謝謝廠商。我是讀字幕寫的，畫面沒看，所以他實際操作長怎樣不清楚。

他點出的問題

開頭那段我覺得講得蠻準。coding agent 可以把 repo 裡每個檔案都讀過一遍，但還是不算真的懂你的 app。資料之間怎麼連、部署在哪、誰依賴誰、昨天晚上哪裡壞掉，這些東西放在 app 跑的那些平台上，不在程式碼裡，agent 從頭到尾沒看過。

這點我自己有感覺。叫 agent 改東西的時候，它對著程式碼推得頭頭是道，可是一碰到「線上那邊到底發生什麼事」，就只能靠我把 log 貼給它。

他推的解法

他的解法就是 OutSystems 的 MCP。照他的說法，Claude Code、Codex、GitHub Copilot 這類 agent 可以直接接進 OutSystems 的開發雲，在同一個 session 裡看懂 app、建置、部署、翻 log。

流程大概是這樣：動手之前，agent 先去查 app 裡真實存在的資料表、畫面、邏輯和角色，把依賴關係畫出來；接著把建置交給 OutSystems 內建的 coding agent（他叫它 Mentor），再發布出去。之後如果壞了，同一個 session 可以把 log 跟 trace 拉回來查原因。

他特別提了一點，agent 是用他本人的身分跑，權限跟他在 OutSystems 裡的一樣，他不能做的事 agent 也不能做。Personal edition 免費，MCP 預設就開著。

我的感想

老實說，這個產品只對本來就把 app 放在 OutSystems 上的人有用，我沒有，所以沒打算去試。業配短片也沒什麼細節可以深究，像它怎麼處理正式環境的資料、權限細到什麼程度，影片裡都沒講。

不過「agent 只看得到程式碼」這個缺口我覺得是真的，跟哪家廠商無關。讓 agent 能讀到部署狀態跟 log，同時權限綁在使用者自己身上、不給它多一分，這個方向我蠻認同的，跟前幾天記下的 讀的權限大方、動手的權限吝嗇 有點像。

這支當作提醒就好，真正有內容的大概要等他下一支長片。
