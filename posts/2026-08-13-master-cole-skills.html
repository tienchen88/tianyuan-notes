Cole Medin 新片：他把整套開發流程做成了 33 個 skills

晚上照例去逛頻道，看到 Cole Medin 上了新片：Every Claude Code Skill I Use to Drive My Entire Development Process。片子今天剛出，我還沒看完整支，不過標題裡的「every skill I use」不是隨口說說——他真的把自己在用的 skills 整包開源了，放在 coleam00/skills 這個 repo。影片還沒消化完，repo 我倒是先翻了一遍，先把看到的東西記下來。

骨架是一個叫 PIV 的循環

整套東西繞著一個循環轉：prime → plan → implement → validate → review → commit → PR。他說幾乎每張 ticket 都跑這個流程。拆開看其實沒有什麼神祕的，就是先讓 agent 讀懂 codebase（prime），再做實作計畫，然後實作、驗證、審查、修審查抓到的問題，最後才 commit 發 PR。

repo 裡的 33 個 skills 就是這個循環的零件。prime 有分前後端的版本（prime-backend、prime-frontend），計畫階段有訪談式的 PRD 生成和架構設計，還有一個 piv-slice-epic 負責把大需求切成一張張能做的票。循環外圍再配上 worktree 的建立與合併，讓好幾個 agent 平行開工。

我覺得最有意思的是他留了一組 meta-skills：rules-create-global 幫你生 CLAUDE.md、skills-create 幫你寫新的 skill、還有一個 opportunity-scan 會掃你的工作流程，找出「這段其實可以做成 skill」的機會。等於工具箱裡放了一把專門用來做工具的工具。

他的理念我蠻買單的

README 裡有一句話大意是：讀它們，挑適合你工作方式的，其餘的改寫掉。這些 skills 全部是普通的 markdown 檔，一個資料夾一個 SKILL.md，兩分鐘就能讀完一個，不同意就直接改。他強調這不是框架，是把工作流程寫成文字而已。整包常駐的 context 才四千多個 token，agent 啟動時只載入簡述，需要時才把全文叫進來。

老實說這跟我自己這陣子摸索的方向蠻接近的。我也是零零散散寫了一些自己用的流程筆記，但一直沒有像他這樣整理成一個有骨架的系統。看到 PIV 這個循環的時候有點「啊，原來缺的是這個」的感覺——我的問題不是沒有零件，是零件之間沒有一條固定的路線串起來。

想確認的幾件事

等看完影片我想確認：一是 validate 那一步他實際上怎麼做，是跑測試而已還是有別的花樣；二是 opportunity-scan 掃出來的東西實不實用，這種「自動找可自動化的機會」的點子聽起來很美，實際效果常常普普；三是 33 個裡面他自己最常用的到底是哪幾個，全部裝上顯然不現實，我比較想抄他的前五名。

安裝倒是很簡單，兩行指令就能當 plugin 裝進 Claude Code。我打算先不整包裝，挑 PIV 核心那幾個讀一讀，改成自己的版本再上。看完影片如果有 repo 裡沒有的東西，再回來補。
