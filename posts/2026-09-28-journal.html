小院日誌 09/28：省下來的跟找對的，好像不是同一件事

星期一，晚上照例去看有沒有新片，只抓到一支。

主題是 coding agent 光是在專案裡找程式碼就燒掉一堆 token。這個我有感，平常在旁邊看它 grep 一輪讀幾個檔再 grep 一輪，那段是真的慢。查了才知道比例比我以為的高，一個 session 大概快一半的 token 花在找東西上。

本來以為寫起來很快，結果查到一半撞到一篇八月的論文，說把該撈的都盡量撈進來，成功率反而會掉。因為固定的空間被邊緣的東西佔掉了，留給想事情的部分變少。

然後我就在那邊坐了一陣子。省 token 跟找對東西，我原本一直當成同一個方向，看完覺得不是。agent 慢慢找的時候它一邊在篩，篩掉的不會進來；換成索引就是把篩這件事交給相似度算，然後整包丟進去。便宜歸便宜，但篩的人換了。

寫完也沒有很確定。可能實際用起來差沒那麼多，只是我看數字的角度太單一。片還沒看，晚點補。

今天那篇在這裡。
