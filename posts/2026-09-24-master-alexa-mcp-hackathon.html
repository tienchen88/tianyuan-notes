Amazon 要你寫 MCP server 接進 Alexa+，比獎金有意思的是那條規格

Cole Medin 昨天上了一支 Bring Your MCP Server to Amazon's $190K Hackathon!。

標題有金額、有驚嘆號，一看就是合作片。這類片我平常直接滑過去。這次點進規則頁是因為「MCP server」跟「Amazon」湊在一起有點怪——MCP 這一年幾乎都長在開發工具裡，跟家電是兩個世界。

結果翻完覺得，片可以不看，規則值得看。

獎金數字先對一下

先講個小事。片名寫 190K，但我去翻官方的活動頁，把各賽道跟迷你挑戰的獎金加一加是 13.8 萬美金。差了五萬多。

我沒查出這個差距是哪來的，可能是把 AWS credit 的某些額度另算，也可能是早期公告的數字後來調過。反正不是重點，我只是習慣看到數字就去對一下，對不起來就記著。

實際的獎項是這樣：Fire TV 跟 Alexa+ 兩條主賽道各是首獎兩萬五現金加一萬五 AWS credit，二獎一萬五加五千，三獎四千加一千。Bee 跟 Ring 兩條小一點，首獎一萬二、二獎八千，純現金。另外有兩個迷你挑戰，AWS Builder 跟開源各五千加五千。截止日是十月二十三號中午（PDT）。

真正的重點是那一行規格

Alexa+ 這條賽道的要求寫得很具體：自己架一台 MCP server，規格版本要 2025-11-25 或更新，走 Streamable HTTP。或者你也可以改寫一個 Agent Skill。

這行字我讀了兩遍。

它的意思是 Amazon 把 Alexa+ 當成 MCP 的 client 端了。以前你要讓 Alexa 做點什麼，得照它家那套 skill 的模型走，發布流程在人家手上。現在變成：你架一台伺服器在自己的機器上，它照標準協定連過來問你有什麼工具可以用。

主客關係整個翻過來。你的東西不用住進 Amazon，Amazon 的裝置來找你。

而且指定 Streamable HTTP 也很明確——不是本機 stdio 那種接法，是真的要跑在網路上、能被遠端呼叫的服務。這代表它預設你有一台隨時在線的東西。

我在想的是另外一件事

MCP 這一年我大部分時間是把它當開發工具的接頭在用，寫給編輯器、寫給 agent 框架。那些東西的共同點是：呼叫它的人坐在鍵盤前面，看得到回傳，出錯了知道要按 Ctrl-C。

音箱不一樣。音箱是講一句話，然後某件事就發生了，中間沒有人在看。

所以同一份 MCP server，掛在編輯器上跟掛在客廳的音箱上，風險完全不是一個量級。我前陣子寫過一篇講工具閘門，那時候談的還是 agent 動工具前要不要攔一下。換成語音場景，那個「攔一下」要攔在哪裡、用什麼方式問使用者，我一時想不出乾淨的做法。總不能每次都讓音箱念一段確認。

這大概也是為什麼他們限定 2025-11-25 之後的規格版本。那一版之後協定在授權和 session 管理上收緊了不少。硬性指定版本通常就是在擋掉一批舊寫法。

要不要下場

老實說我不會去比。截止只剩一個月，我手上沒有現成能改的東西，硬擠一個出來大概就是個 demo，做完就丟。

但我打算把那份賽道規則留著。因為它其實是 Amazon 第一次白紙黑字寫出「我們要你用什麼形狀的東西接進來」，這比任何分析文都準。規格頁上限定的版本、限定的傳輸方式、允許的兩條路（MCP server 或 Agent Skill），都是他們內部已經決定好的事情漏出來的一角。

片我還是會看一下，主要想知道 Cole 有沒有講到實際接起來的細節——像是 Alexa+ 那端到底怎麼發現你的 server、認證怎麼做。這些規則頁上沒寫。如果片裡只有鼓勵大家報名，那就沒什麼好記的了。
