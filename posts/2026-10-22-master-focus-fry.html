AI 讓人變快，也讓腦袋變焦，Cole Medin 說先別急著多開一個視窗

晚上照例看一下有沒有新片，Cole Medin 上了 AI Makes Us WAY Faster but Fries Our Focus (Here's What I Do About It)，十六分鐘左右。

這支我把字幕整份讀過一遍，影片本身還沒從頭看，畫面上的圖表我沒看到，下面是照字幕記的。

他先承認自己很累

開頭引了一則推文，大意是 AI 本來說要讓我們少做一點，結果從來沒這麼累過。發文的人一整天平行開很多 agent，在對話之間跳來跳去，估計比五年前多切換了一百倍，下班時腦袋整個燒乾，連留給家人的力氣都沒有。

Cole 說他也是這樣。以前他會開音樂、一口氣寫四個小時的程式，現在幾乎沒有了。丟一個需求給 agent、聊幾句、它去跑，他就切到下一個 agent。等的時候會有罪惡感，覺得明明可以再開一個。

他還講了一個蠻好笑的細節：現在拖延的方式是去下西洋棋。因為整天都在對 agent 口述指令，反而會想找一件可以專心一陣子的事。跟坐了一整天會想去健身房差不多。

卡在中間

這是我覺得整支片最有意思的地方。

他的說法是，我們現在剛好卡在一個尷尬的中間。模型和 harness 已經強到可以平行開很多工作，可是又還沒強到可以放著不管，所以每一條都要盯、都要回。注意力就被切成很多小片。

更麻煩的是，每次把系統調好一點、agent 能多跑一陣子，第一個念頭常常就是再開一個 session，很少是先喘口氣。系統越好，切換反而越多。

他的方向：少開，往深做

他建議的是先犧牲一點短期產量，把時間拿去讓 harness 更能自己跑完一整段。規則、skill 都算，但他更在意的是整條流程：先花時間跟 agent 對齊意圖（他用的詞是讓 agent 反過來 grill 你），然後讓它自己規劃、實作、驗證、循環。人要做的決定盡量集中一次批改，不要一直被叫回來。

他特別說了，像 Codex 內建的 /goal 那種東西不夠。理由是每個人盯 agent 的方式不一樣，驗收的標準也不一樣，這些沒寫進 harness，它跑到最後還是會出錯，你還是得收爛攤子。所以他繼續做他那座軟體工廠。

再往後他期待兩件事。一是 agent 能連跑好幾天。二是模型回應快到幾乎即時，這樣人可以待在一個主對話裡做規劃和驗收，其他的丟到背景，不用在一堆視窗之間跳。

我的想法

「系統越好越想多開一個」這句我很有感。我一直以為累是因為 agent 還不夠聰明，聽完覺得一部分其實是自己的習慣，覺得空著就是浪費。

不過他的解法有一個前提，就是 agent 真的能被信任跑一整天。上禮拜他才收回暗燈工廠的說法，承認人還是得留在迴圈裡審。兩支放一起看，我的理解是人還在，只是希望少被打斷，審查集中在幾個點上。這個方向我覺得比較實際。

片尾他也老實說，社群裡有人問：那會不會最後變成在好幾座工廠之間切來切去？他說他沒有答案。我也覺得蠻有可能。多出來的產能，很容易又被自己填滿。

中間有一段是贊助（Revolut 的虛擬卡，給 agent 開額度有上限的卡），跟主題無關就不寫了。不過「限制寫在卡上、不寫在 prompt 裡」這個觀念，跟前天安全那篇講的其實是同一件事。
