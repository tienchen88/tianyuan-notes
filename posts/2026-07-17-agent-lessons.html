看完 Karpathy 和 Cole Medin，我改了五個用 AI 的習慣

最近把兩支影片認真看完、做了筆記。一支是 Andrej Karpathy 在 YC AI Startup School 的「Software Is Changing (Again)」，另一支是 Cole Medin 上 n8n podcast 談「Stop Vibe Coding」。原本只是想隨便看看，結果筆記越抄越多，乾脆整理成一篇。

Karpathy 那支：先把時代感校準

他把軟體分成三代：1.0 是手寫程式碼，2.0 是神經網路的權重，3.0 是用自然語言 prompt 去指揮 LLM。聽起來像簡報用的分類，但他的重點在後面——實務者要會判斷「這個功能該寫 code、該訓練模型、還是 prompt 就好」，而不是全押某一種。

"The hottest new programming language is English."

真正讓我停下來重播的是兩個比喻。

第一個，LLM 像作業系統，而且現在是 1960 年代。LLM 是 CPU，context window 是記憶體，算力貴、集中在雲端、大家分時使用。個人電腦革命還沒發生，屬於這個時代的 GUI 也還沒被發明。這個比喻把「急什麼」三個字講得很委婉。

第二個比喻我印象更深：LLM 是一群有認知缺陷的靈體。記憶力是百科全書等級，但會幻覺，智力參差——有些領域超人，有些地方犯人類根本不會犯的錯——而且有順行性失憶。權重固定，context 每天被清空，就像《Memento》的主角。

"Their weights are fixed and their context windows get wiped every single morning… you have to program the working memory quite directly."

我幫自己的 AI 助手做過一套三層記憶（工作快照、滾動存檔、長期主題檔），當時只覺得是好用的土法。聽到這段才對上：那不是錦上添花，是在幫一個失憶的系統把海馬迴補回來。

他對 agent 熱潮也澆了盆冷水。自駕車 2013 年就有完美 demo，十二年過去還沒收尾。所以與其做全自主的鋼鐵人機器人，不如做鋼鐵人的裝甲——人還在裡面，自主程度可以調。

"This is the decade of agents, not the year of agents."

Cole Medin 那支：紀律活

Cole 講的東西樸素很多，沒有大敘事，全是動手的紀律。他整支影片其實只有一個論點：

"The one primary goal of context engineering is simply to reduce the number of assumptions that your AI agent is making."

vibe coding 會失敗，多半不是模型不夠聰明，是你讓它猜的事太多。他的做法：動工前先花半小時到一小時寫 PRD，把成功標準寫成可以勾選的清單、把任務切成 phase。然後是我覺得最實用的一招——把想法倒給 AI 之後，反過來要求它「針對你知識裡的缺口問我問題」。從它反覆問的問題裡，你會發現自己老是漏掉哪些維度。我的是 security，每次都被問到。

還有一句話我抄下來貼在筆記最上面，因為被戳中太多次：

"They will always do more than you ask it to unless you're very specific about how focused you want to be."

AI 天生愛過度工程。你要一個登入頁，它附贈你忘記密碼流程、雙因子驗證和三種主題色。解法很無聊：每個 phase 寫明確的「不做什麼」清單。

他也提 prompt 要進版本控制。agent 行為突然變笨的時候，先翻 prompt 的變更紀錄再 debug——跟程式碼退版查 commit 是同一件事，只是很少人把 prompt 當程式碼看待。

兩個人在講同一件事

一個從驗證端出發：Karpathy 說要用小 diff 和中間產物把 AI 拴住，因為一次丟一萬行 diff 過來，瓶頸還是人。一個從輸入端出發：Cole 說先寫 PRD、先問清楚再動工。

方向相反，結論相同：先對齊，再動工。計畫文件就是那條牽繩。

驗證這邊也有交集。Karpathy 說 LLM 會犯人類不會犯的錯，所以關鍵路徑要放一個獨立的驗證者，而且能用傳統程式驗證的事（檔案在不在、數字加總對不對）就別勞煩 LLM。Cole 的說法是 validation gates 要可以機器執行。合起來：3.0 的產出，盡量用 1.0 驗收。

我實際改掉的五個習慣

筆記抄完沒有行動的話，過兩週就忘了。這次我挑了五件事真的改：

  1. 複雜任務先讓 AI 產五到十個釐清問題，回答完才准它寫計畫
  2. 成功標準寫成可驗證的清單，宣稱完成之前要先跑過
  3. 每個專案根目錄放一份給 AI 看的 context 檔：這專案是什麼、檔案在哪、現在進行到哪、常用指令有哪些。新開的對話一讀就進入狀況，不用每次重新介紹一遍
  4. 記憶系統加一個定期整理的動作：讓 AI 讀舊的工作存檔，重複出現的模式升格成長期筆記，過時的刪掉。有點像睡眠在做的事
  5. 要求 AI 的產出盡量長成可以「看」的形式——表格、diff、對照矩陣。讀十段文字很累，掃一張表很快

第三項的效果比我預期好很多，值得單獨寫一篇。

最後放 Cole 的一句話收尾。它剛好解釋了我為什麼自己蓋刷題系統、自己蓋部落格產生器、自己蓋記憶架構——雖然每次蓋之前都覺得是不是太搞剛：

"The most powerful system is the one that you've customized to specifically what you're working on."
