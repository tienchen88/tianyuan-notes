兩支影片改變我用 AI 的方式：Karpathy 與 Cole Medin 筆記

最近認真看了兩支影片，做了完整筆記。一支是 Andrej Karpathy 在 YC AI Startup School 的演講「Software Is Changing (Again)」，一支是 Cole Medin 在 n8n podcast 談「Stop Vibe Coding: Context Engineering & RAG」。一個講產業典範，一個講動手紀律，高度差很多，但抄完筆記回頭看，兩個人其實在講同一件事。

Karpathy：軟體第三次典範轉移

他的框架很簡潔：Software 1.0 是手寫程式碼，Software 2.0 是神經網路權重，Software 3.0 是用自然語言 prompt 來 program LLM。三種各有優劣，實務者的功課是判斷「這個功能該寫 code、該訓練模型、還是該 prompt」——而不是全押其中一種。

"The hottest new programming language is English."

我最受用的是他對 LLM 的兩個比喻。

第一個：LLM 是作業系統，而且現在是 1960 年代。 LLM 是 CPU，context window 是 RAM，算力昂貴、集中在雲端、以分時方式使用——personal computing 的革命還沒發生，屬於這個時代的 GUI 也還沒被發明出來。這個比喻把「現在該做什麼」講得很清楚：別急著宣告終局，基礎設施還早。

第二個：LLM 是有認知缺陷的 people spirits。 它有百科全書式的記憶，同時卻會幻覺、智力參差（某些領域超人、某些犯人類不會犯的錯），而且有順行性失憶——權重固定、context 每天被清空，不會跨 session 累積專業。他用電影《Memento》比喻：

"Their weights are fixed and their context windows get wiped every single morning… you have to program the working memory quite directly."

這句話直接解釋了為什麼我要幫自己的 AI 助手蓋三層記憶系統（工作快照／滾動存檔／長期主題檔）——不是錦上添花，是在補一個作業系統層級的缺陷。

第三點是他對 agent 熱潮的降溫：自駕車 2013 年就有完美 demo，十二年後還沒完全解決。該建的是鋼鐵人的裝甲（augmentation、自主程度可調），不是鋼鐵人機器人（全自主）。

"This is the decade of agents, not the year of agents."

具體的設計語言是 autonomy slider：像 Cursor 從 tab 補全到全 repo 自主改動有好幾個檔位，使用者依任務決定讓渡多少自主權。另一個是 generation-verification loop：AI 負責生成、人負責驗證，整個合作的效率取決於這個迴圈轉多快——所以 AI 的產出應該是可視化的 diff、表格、可以「看」的東西，因為人腦讀字很慢、看圖很快。

Cole Medin：context engineering 只有一個目標

Cole 那支的核心句子我直接抄在筆記最上面：

"The one primary goal of context engineering is simply to reduce the number of assumptions that your AI agent is making."

Vibe coding 之所以失敗，通常不是模型不夠聰明，而是你讓它猜的事情太多。他給的解法都很樸素：

  • 先花 30–60 分鐘寫 PRD 再動工：定義成功標準（可勾選的清單）、使用者旅程、切成 phase 的任務分解
  • 反向提問：把想法倒給 AI 之後，明確要求「針對你知識裡的缺口反問我」——從它反覆問的問題裡，你會學到自己老是漏掉哪些維度（我的是 security）
  • 成功標準要寫成可機器驗證的形式：測試指令、lint、smoke check——「勾完這十個框就是完成」，不留模糊空間
  • AI 天生愛過度工程：「除非你講得非常明確，它永遠會做得比你要求的多。」所以每個 phase 都要寫明確的 out-of-scope 清單
  • Prompt 也要 version control：agent 行為劣化時，先看 prompt 的變更史再 debug

兩人的交會點

Karpathy 說要用小 diff 和中間產物把 AI「拴住」（keep AI on a leash），因為一次丟給你一萬行的 diff，瓶頸還是人；Cole 說先寫 PRD、先問清楚再動工。一個從「驗證端」出發、一個從「輸入端」出發，指向同一條紀律：

先對齊，再動工。plan 就是那條牽繩。

還有一個交會點在驗證：Karpathy 說 LLM 會犯人類不會犯的錯，所以關鍵路徑要放獨立 context 的驗證者，能用傳統程式驗證的（檔案存在、數字加總）就不要用 LLM 驗證；Cole 說 validation gates 要可機器執行。翻成一句話：Software 3.0 的產出，盡量用 Software 1.0 驗收。

我真的落地的五個行動

筆記的價值在行動。整理完之後我挑了五件事改進自己的 AI 工作流：

  1. 規劃前置提問關卡——複雜任務先讓 AI 產出 5–10 個釐清問題、回答完才寫計畫（Cole 的反向提問 + Karpathy 的 leash）
  2. 成功標準寫成可驗證的 checklist，宣稱完成前必須跑過驗證關卡
  3. 每個專案根目錄放一份 agent 看得懂的 context 檔——專案是什麼、關鍵路徑、目前狀態、常用指令，新開的 session 一讀就有完整脈絡（Karpathy 的 llms.txt 思路）
  4. 記憶系統加「睡眠鞏固」——定期讓 AI 讀舊的工作存檔，把重複出現的模式升格成長期筆記、刪掉過時條目，模仿人腦睡眠時做的事
  5. AI 產出一律要求驗證友善——表格、diff、對照矩陣，並且把「每輪驗證花幾秒」當成工作流的核心指標

最後放一句 Cole 的話收尾，我覺得它同時解釋了為什麼值得自己蓋題庫系統、自己蓋部落格產生器、自己蓋記憶架構：

"The most powerful system is the one that you've customized to specifically what you're working on."
