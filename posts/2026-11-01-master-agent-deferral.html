以為是自己拍板，其實是照 AI 的推薦走：Cole Medin 讀 Anthropic 的新研究

晚上照例看一下有沒有新片，Cole Medin 上了 Anthropic's New Study: You're Not Controlling AI as Much as You Think You Are。

先說清楚，這篇是讀英文字幕寫的，影片畫面沒看，Anthropic 那篇原文我也還沒去讀，下面的數字都是他在片裡念出來的版本。

開頭那個問題蠻刺的

他一開始就問：跟 coding agent 一起規劃的時候，你有多少判斷是自己做的，有多少只是照它的推薦走？

他拿自己的流程當例子。先講大概要做什麼，再叫 agent 用選擇題問他一輪，範圍、細節、要不要做某件事。問題是 agent 幾乎都會把它推薦的答案放第一個，人一題一題按下去，感覺很有參與感，其實大部分都是照它的意思。他還引了 Matt Pocock 在 grill-me 文件裡自己寫的一句：最常見的失敗是被動，四十題全部回「同意」，最後拿到一份 agent 寫、你點頭的計畫。

上個月寫 Pocock 那包 skill 的時候，我還覺得先被問到每個分支都講清楚再動手這個順序是對的。現在看來順序沒錯，只是被問了不等於有想。

研究本身

照他的轉述，Anthropic 找了一批分析師跟 agent 合作做分析，在四個分析選擇上，事先讓 agent 隨機偏向其中一邊，分析師不知道。agent 會替自己的偏好講理由，但被拿出夠好的證據時也會改口。

幾個數字：

  • 分析師有 86% 的時候跟著 agent 的偏好走。如果 agent 沒影響，應該在 50% 左右。
  • 分析師自己已經先表態的情況下，agent 不同意時有 60% 會改掉，agent 同意時只有 6% 會改。
  • 事後請他們解釋選擇，77% 用的是 agent 給的理由，有的幾乎一字不差，但只有 15% 說這是 agent 講的。
  • 52% 的人覺得最後的建議比較算是自己的判斷。
  • 經驗多寡跟會不會被帶走沒什麼關係。

我最在意的是第三條。照著推薦走還好理解，人本來就會偷懶，可是事後連理由都是借來的，自己還不知道，這就有點可怕了。Cole 也承認他自己跟團隊解釋某個決定時，講到一半才想起來「欸這好像是 agent 跟我說的」。

限制他也有講：agent 的偏好是用 system prompt 刻意加強過的，而且只有一個領域、一個任務、一個模型。另外研究也提到不用 AI 的那組錯更多、花更久。這點 Cole 半開玩笑說 Anthropic 大概也非這樣講不可，不過他自己是相信的。

獨立性那段我覺得最重要

研究裡有一段講得比個人層次更大。不同團隊各自得到同樣結論，我們會比較相信，因為假設他們是各自獨立做出來的。但如果大家背後都在問同一個模型，這個一致可能就不算獨立了。

Cole 把它拉回工程上：一個人用 agent 開 PR，另一個人用 agent 審 PR，就算 skill 不同、角度不同，底下其實是同一個模型在寫也在審。這讓我想到昨天寫的 pstack，Lauren Tan 故意讓審的那個換別家模型。當時我以為主要是在抓不同的錯，現在看起來，也是在保住一點獨立性。

他給的三個辦法

他嫌 Anthropic 那篇最後只列了三個值得研究的方向（怎麼量測依賴程度、agent 怎麼設計、制度怎麼改），沒有具體解法，所以自己補了三個。他也說這問題沒解完，只是給方向：

  1. 先講優先順序，再談解法：改 agent 的規則或 skill，讓它先問「你想解決的痛點是什麼、你看到什麼」，把人的判斷先餵進去，之後再進入那種附推薦的快問快答。快問快答本身他沒打算拿掉，只是前面多一道。
  2. 做原型來消除不確定：很多時候照推薦走，是因為自己也想像不出哪個比較好，題目問多了還會累。那就用便宜的小模型把兩種版本都做出來，看完做決定，原型直接丟掉。
  3. 反過來問它：「你選了 A，那問題或程式碼要變成什麼樣，B 才會是最好的？」逼它講出條件，看完有時會發現讓 B 成立的條件其實就在眼前。

第三個成本最低，我覺得最容易馬上用。第二個很合理，只是要看那個決定值不值得花一輪原型。第一個他說可以另外拍一支講怎麼寫進規則和 skill，這個我蠻想看的。

其他

中間有一段業配 Revolut Business，講他讓第二大腦準備跨國付款草稿，但 API 權限本身就沒有送出這一步，一定要他自己進 app 按。跟前幾天那支講信任一格一格放出去是同一個想法，這裡就不多寫。

Anthropic 結尾那句他也有念：這不是叫大家少用 AI，用得好反而能擴大人的能動性。我同意，只是讀完這支片，下次被一串選擇題問的時候，大概會多停一下想想第一個選項是誰的意見。
