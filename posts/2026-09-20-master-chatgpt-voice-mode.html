「用嘴巴完成所有工作？」那個問號我覺得是重點

Gary Chen 前天上了新片：ChatGPT Voice Mode 實測，用嘴巴完成所有工作？。

標題最後那個問號我覺得放得很好。這種片如果寫成「用嘴巴完成所有工作」，我大概會直接猜是在推功能；加了問號，語氣就變成「我去試了，結果不太是那樣」。當然我還沒看，也可能只是習慣性的標點。

片子還沒看，我先去把桌面版語音這回事查了一遍，因為我對它的印象還停在手機上那個會跟你聊天的圓球。

它跟語音輸入真的不是同一件事

ChatGPT Voice 是七月底上桌面的，Mac 跟 Windows 都有，底下跑的是他們叫 GPT-Live 的東西。跟一般語音輸入最大的差別在於它是雙向的：你可以在它還在講的時候插話、中途補條件、或者叫它先等一下。

這個我一看就有感覺。以前用過的語音輸入本質上就是個高級一點的鍵盤，你講完一段，它吐一段文字，然後你要回去用滑鼠改。一旦講錯，修的成本比重打還高。能插話是完全不同的互動——講到一半發現方向不對，直接打斷改口，這才像跟人講話。

功能上更誇張的是它可以用嘴巴開任務。官方給的例子大概是「開一個 Codex 任務去測那幾個失敗的項目，同時幫我看一下進行中的工作、把卡住的整理出來」這種句子。也就是你不是在跟它聊天，是在派工，而且可以對已經在跑的 agent 補指令，進度和卡關會回報到你當下那段語音對話裡。

macOS 上還多一個叫螢幕上下文的東西，會抓你當前視窗的畫面和可讀取的文字。所以你說「幫我看一下這個」，它知道「這個」是什麼。

限制也查到幾條：一個 session 只能開一段語音對話；語音用量算在訂閱方案的額度裡；用嘴巴開出去的 Work / Codex 任務，吃的是原本的 agent 工作額度；工具權限沿用你本來設定的那套，要不要給檔案、要不要讓它操作電腦，還是照原本的規矩走。方案要 Plus 以上。

我最想知道「不適合口述的部分」怎麼辦

那個問號如果真的是在質疑，我猜質疑的點會落在這裡。

講話比打字快，這件事沒什麼爭議。但快是對某些東西快。描述一個意圖、抱怨一個現象、交代一個大方向，用嘴講確實順很多。可是路徑、參數、變數名字、任何需要精確到字元的東西，用嘴講是災難。我試過口述一個資料夾路徑，唸完發現底線變成減號、大小寫全錯，光是校對就比自己打完慢。

所以「所有工作」大概不成立，能成立的是某一層工作。問題是那一層在哪裡，以及你在兩種輸入方式之間切換的成本有多高。如果我每講三句就要伸手去鍵盤改一個字，那整件事的節奏就散了，還不如全程打字。

螢幕上下文可能就是為了處理這個。你不用唸出那個檔名，你指著它說「這個」。我覺得這是整套功能裡最關鍵的一塊——它把口述最弱的環節（精確指涉）交給眼睛去做。同時它也是我最猶豫的一塊，因為那等於預設它一直看著我的螢幕。這題跟之前那支讓 agent 直接開我電腦的片撞在同一個地方，只是換了個更溫和的說法。

額度那條我一看就笑了

「語音開出去的任務吃原本的 agent 額度」——這句寫得很不起眼，但我覺得它會是實際用起來最有感的限制。

派工的門檻降低，派出去的量就會變多。以前要開一個任務，你得停下來、切視窗、把要求打成字，這個摩擦本身就是一道篩子，會濾掉一些其實不用做的事。變成一句話就能丟出去之後，那道篩子就沒了。我猜很多人會在第一個禮拜爽爽用，然後月中發現額度見底，跟我八月那時候的處境一樣。

這不是功能的問題，是人的問題。工具把成本從「我的時間」搬到「我的額度」，而後者我平常不太有體感。

我的真正障礙其實不在技術

老實說，語音這一塊我觀望很久了。上次看 Rime 那支的時候我也是這個態度。

而我一直沒用起來的原因蠻俗的：我沒辦法對著電腦一直講話。家裡有人的時候不行，安靜的時候自己聽自己講也怪。這跟模型好不好、延遲低不低完全無關，是社交跟心理上的阻力。我猜這也是語音類工具的示範影片看起來都很順，換到自己手上就用兩天的原因之一。

所以我對這支片真正期待的，不是功能清單——那我自己查得到——而是他實測完之後那個問號的答案。用了幾天，哪些事他真的改成用嘴巴做了，哪些試過又退回去打字。這種東西只有實際用過的人講得出來。

片晚點看，看完有想法再補。
